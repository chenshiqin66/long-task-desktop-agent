# 路线图

这一页分四部分：多个会话如何同时执行、有意不做的设计及理由、已经落地的改进、以及接下来可以继续补的部分。前两部分是设计取舍，后两部分是实际状况。

## 不同会话同时执行

这里的 5 指同时处于执行中的 runtime 个数，不是把主区切成 5 块。主区仍然只有一页。

`AgentRuntime` 只服务一轮，不在内部处理多轮。同时执行由外层的 `SessionRuntimePool` 负责，键是规范化后的「工作区路径 + `sessionId`」。路径里的斜杠和大小写先统一，`C:\work` 和 `C:/work` 不会各占一个名额。

- 一条会话正在跑时再发送，得到 `busy`；续跑留在同一个对象里完成。
- 每条会话各有一份权限门和提问门，答复靠 `request_id` 配对，互不串线。
- 最多 5 个对象同时执行。第 6 次发送得到「已有 5 个会话在执行」。收件箱唤醒超过上限时不报错，回执留在队列里，等那条会话再打开时再试。
- 父轮次结束且没有后台子代理时，释放这个对象；下次发送按当时的配置新建。仍在跑的、或还有后台子代理的会话，继续沿用开始时的配置。后台子代理还在时，侧栏的圈继续转，名额和转圈一一对应。这时输入框已可再发；停止按钮只取消当前这一轮，不去打断已经转入后台的子代理。
- 切换或新增工作区不会拆掉别的会话正在跑的对象。删除会话会取消这一轮，并停止它的后台子代理。重新加载页面会取消所有正在执行的对象，不留下没人能回答的 runtime。
- 每个对象只监视自己的会话，一条会话结束不会把续跑切到另一条上。

界面：

- 输入框只跟当前这一条会话相关。没在跑就能发送；在跑时按钮变成「停止」，只取消这一条。别的会话在跑时，这里照常输入。
- 流式文字、工具条和权限条写进该会话自己的对话节点。切走后节点保留，后台继续往里写。
- 侧栏里每个占着名额的会话各自转圈，包括父轮次已结束、后台子代理仍在跑的会话。停在权限确认或「等你回答」且你正在看别处时，该项换成不转动的等待标记，任务栏图标也会闪。

当前的隔离边界：

- 同一工作区的两条会话各写各的 `.agent/sessions/<id>/`，对话互不串线。
- 跨会话的 `output_dir` 互斥尚未实现。`output_dir` 是模型每次 `worker` 调用时填的相对目录，不是按会话分配的文件夹，两条会话写同一路径时，后写的覆盖先写的。会话之间彼此独立是有意的：跨会话加锁会让它们互相等待，还要引入全局注册表。若以后要做共享目录的协作，再补全局锁。
- 读文件、改文件和跑命令都作用在同一个项目目录上。这是工作区模型本身的结果，不是会话隔离的漏洞。
- 解释侧栏同一时刻只跑一个。它是辅助问答，全局一份状态即可，和主会话仍可同时进行。
- 没有预先拉起空进程，会话需要时才创建对象。
- 同一个用户数据目录只允许一个进程。再启动一次会退出，并把已有窗口带到前面，这样不会有第二份 stdio 的 MCP 子进程被拉起。
- 应用重启后，磁盘上的会话保留，但正在跑的那一轮已经结束，不会自动续上。

## 有意不做的设计

下面每一项都是取舍，理由写在同一条里。

- **主会话不写记忆。** 主会话的上下文里一直留着网页、文件和工具结果，没有哪一刻是干净的。让它写，外部文字就能变成以后每一轮都带上的规则。它发现过时条目时会告诉你，由你改，或由你一句话让后台改。详见 [主会话为什么不能写](memory.md#主会话为什么不能写)。
- **指令文件只读用户级和项目级两份。** 不展开 `@path`，不读父目录和子目录，也没有按路径生效的规则。范围小，就能说清楚哪些内容进了上下文。项目级文件若是指向工作区外的符号链接，则不加载：一个仓库可以把 `AGENTS.md` 链到私密文件，加载它就等于把那份文件发给模型服务商。
- **记忆是你能审阅的文件。** 不做向量检索，不每轮另调模型挑选，也不自动整理。每条都看得见、能改，自动改写会让内容在你不知情时变化。子代理不读写记忆，解释侧栏也不用记忆和指令文件。记忆不跨机器同步，也不在团队里共享。
- **子代理只有 `explore` 和 `worker` 两种，不能自定义，也不能再派子代理。** 类型就是工具权限：选类型就是选工具，没有临时放宽的入口。
- **会话内没有工作笔记。** 长任务里被整段丢掉的旧工具往返另作一个模块处理，不混在记忆里。
- **子代理的四个文件不单独在主区打开。** 它的工具行挂在父会话下面，在父会话里就能看到它在做什么。
- **文件页就是主区里的四个标签，没有单独的检视面板。** 信息集中在一处，不分散。
- **MCP 不做 OAuth，也不做资源和提示词。** OAuth 是另一套登录产品；资源和提示词不在工具调用这条路径上。
- **不估算 token 数。** 流里没有 `usage` 时，父会话、子代理和解释都不写数字。估算出来的数字看起来精确，实际可能是错的，宁可留空。
- **应用不根据你的话猜模型类型。** 选错接口导致的失败会把服务返回的错误原样显示。语音合成 / 识别已走火山 openspeech；麦克风听写不自动发送。
- **重新打开会话时，「已记住」那一行不再重画。** 它只在出现的那一刻显示。

## 已落地的改进

这里记的是已经修好的问题。

- **生视频走派欧云 MiniMax H3。** 四个型号各自保存参数；异步创建任务并查询；结果写入 `videos/`。参考素材（r2va）已接通；对话里尚未提供本轮覆盖控件。
- **语音合成 / 识别走火山豆包 openspeech。** 旧配置 `kind: audio` 读入时当作 TTS。HTTP TTS 与 WebSocket ASR（上传 + 麦克风）；结果写入 `audios/` 或转写文本。手工验收：用豆包语音 Key 合成一条 mp3 → 上传 mp3 转写 → 麦克风写入输入框且不自动发送。
- **只开一个窗口。** 同一个用户数据目录里再启动一次，新进程退出，并把已经开着的窗口带到前面。
- **`write_file` 不跟随已有的符号链接。** 目标已经是符号链接时，写入前拒绝。
- **递归删除家目录和系统目录直接拒绝。** 整盘、根目录、用户主目录，以及 `C:\Windows`、`C:\Users`、`C:\Program Files`、`C:\Program Files (x86)`、`/etc`、`/usr`，点过允许也不执行。单独一个变量再只加 `/` 或 `/*` 同样拒绝。还认不出的写法见下一节。
- **重启打断的 deferred 子代理会放开任务。** 下次打开会话或再发送时，进程编号对不上、仍标着在跑的记录会把领取的任务放回待办，并记成中断。
- **一个读不出来的任务文件不再挡住整张清单。** 别的任务可以新建、领取和完成。这个文件留在原地，依赖它的任务仍算被挡住。
- **子代理不能提问，也不能再派子代理。** 它若调用这两个，得到的是一条错误结果，这一轮继续。父会话里这两个名字仍由 runtime 接住，不会变成一条普通结果。
- **超时或取消留下已经拿到的输出。** shell 和技能脚本都如此，这一次仍算失败。输出按 UTF-8 解码。命令输出顶到上限时仍算成功，并在末尾标出被截断；技能脚本顶到上限时还没有这句标记。
- **请求带用量字段时的兼容。** 网关因此返回 400，且正文提到这个字段时，去掉它再试一次。
- **搜索有自己的模型类型。** 在模型页添加类型为「网搜」的模型，`web_search` 就指向它。它和对话模型各有一个「当前」，同时生效，不跟随对话模型。
- **配置先写到临时文件再换上。** 坏的 `config.json` 会改名备份，启动时说明备份路径。应用仍以空密钥启动。
- **解释栏里的链接和主对话一样可以打开。**
- **「重新问」再发原来的文字和原来的图片、视频。** 输入框里正在写的字和已经选上的附件留在原地。两条消息用会话里的同一个图片或视频文件。只有图片或视频、没有文字的问题也有这个按钮。
- **续跑期间暂存的那句话会附上技能正文。** 找不到或已停用就跳过，这一轮不因此失败。完成通知本身不附正文。

## 后续改进

下面每一条都写了现状、为什么这样，以及可以往哪里补。

- **`write_file` 对硬链接不做检查。** 现状：目标若已是指向工作区外的硬链接，写入会改到那一份。原因：硬链接在路径层面和普通文件无法直接区分，目前的检查只针对符号链接。可补的方向：读取文件的链接计数，大于 1 时拒绝；Windows 上的表现需要实测后再定。
- **shell 删除的识别范围有限。** 现状：`"$DIR/build"`、先 `cd` 再 `rm -rf *`、写在脚本里的删除，以及 `~/code` 这类再往下一层的目录，不在永不执行的名单里。原因：这些写法要到运行时才知道真正的路径，静态判断无法完整覆盖。这些情况仍落在确认门上，不会静默执行，但点过「允许这一轮」之后会执行。可补的方向：展开路径后再判断，或把更多目录加进名单。
- **重启打断的 deferred 子代理没有回执。** 现状：下次打开会话或再发送时，仍标着 `running` 的子代理会把领取的任务放回 `pending`，meta 记成中断。原因：子代理在进程内运行，进程结束后没有可以接续的状态；把任务放回待领取，是为了不让活丢掉。父会话收不到那次未完成的回执。可补的方向：把中断原因写进父会话的完成通知。
- **读不出来的任务文件留在原地。** 现状：别的任务照常新建、领取和完成，新编号会跳过这个文件占着的号；对这个坏编号的领取、完成、修改、删除都会被拒绝。原因：不擅自修复或删除文件，免得误删。依赖它的任务保持被挡住的状态，因为无法确认它是否已完成。可补的方向：在界面里提供查看和手动处理坏文件的入口。
- **`web_search` 只认 DeepSeek 的返回格式。** 原因：目前只对接一家搜索服务。网搜模型的 Base URL 和 API Key 决定请求发往哪里，不回退到对话模型的密钥。可补的方向：加一层返回格式适配，接入别家接口时只需写一个适配器。
- **Composer 品类一级。** 已落地：Chat / 生图 / 合成语音 / 生视频 Tab、`composerKind` + `currentModelByKind`、按品类过滤模型、新建会话回 Chat、生视频摘要芯片与本轮覆盖。详见 [设计](superpowers/specs/2026-11-23-composer-kind-design.md)。后续可补：生图参数芯片、按模式切换附件槽布局、有声成片开关。
- **配置文件改名失败时的保存。** 坏的 `config.json` 改名为 `config.json.broken-<时间>`，不自动覆盖原文件，这是为了不丢配置。应用仍以空密钥启动，需要你把备份改回原名。改名失败时原文件还在，之后的保存会覆盖它。可补的方向：改名失败时暂停保存并提示。
- **部分测试脚本没有接进 `npm test`。** 例如 `packages/app/scripts/test-markdown.mjs`，它可以在普通 Node 里直接跑，但需要先构建 app 的产物，目前单独手动运行。
