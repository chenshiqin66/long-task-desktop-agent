# 路线图与已知问题

这一页写三件事：不同会话怎么同时执行、刻意还没做的事，以及读代码时发现、还没修的问题。前两节是设计取舍，第三节是欠账。

## 不同会话同时执行

5 是同时处于执行中的 runtime 个数，不是把主区切成 5 块。主区仍然只有一页。

`AgentRuntime` 仍然只服务一轮，没有改成内部多轮。同时执行靠外面的 `SessionRuntimePool`，键是规范化后的「工作区路径 + `sessionId`」。路径里的斜杠和大小写先折成同一种写法，避免 `C:\work` 和 `C:/work` 各占一个名额。

- 一条会话正在跑时再向它发送，仍是 `busy`；续跑留在这个对象里面。另一条会话另建一个对象，各自一份权限门和提问门，答复仍靠 `request_id` 配对。
- 正在执行的对象最多 5 个。第 6 次发送得到 `已有 5 个会话在执行`。第 6 次收件箱唤醒不报错，回执留在队列里，等名额空出来再打开那条会话时再试。
- 父轮次结束、并且没有后台子代理时，丢掉这个对象；下次发送按当时的配置新建。正在跑的那条，以及还有后台子代理的那条，继续用开始时的配置。后台子代理还在时，侧栏的圈继续转，名额和转圈一致。这一轮本身已经结束，输入框可以再发，停止按钮也不会去取消已经在后台的子代理。
- 切换或增加工作区不再拆掉别的会话还在跑的对象。删掉会话会取消这一轮并停掉它的后台子代理。重新加载页面会取消当时所有正在执行的对象，不再留一个还在跑、却没人能回答的 runtime。
- 每个对象只监视自己那条会话，避免一条跑完把续跑切到另一条上。

界面：

- 输入框只看当前这一条。没在跑就能发送；正在跑则按钮是「停止」，只取消这一条。别的会话在跑时，这里照常打字。
- 流式文字、工具条和权限条写进该会话自己的对话节点；切走后节点留着，后台继续往里面写。
- 侧栏里每个还占着名额的会话各自转圈，包括父轮次已经结束、后台子代理还在跑的那一条。某条停在权限确认或「等你回答」、而你正看着别处时，那一项换成不转动的等待标记，任务栏图标也会闪。

这一版不隔离的部分：同一工作区的两条会话各写各的 `.agent/sessions/<id>/`，对话不会串。`output_dir` 仍是模型在每次 `worker` 调用里填的相对目录，不是按会话分配的文件夹；这一版也不做跨会话互斥，两条会话写到同一路径时，后写的盖过先写的。读文件、改文件和跑命令同样作用在同一个项目目录上。解释侧栏仍是同一时刻只跑一个。不预先拉起空进程。应用重启后，磁盘上的会话还在，正在跑的那一轮已经断了。

## 刻意还没做的

- 没有跨会话记忆。
- 没有用户自定义工具，扩展能力靠技能。
- 子代理只有 `explore` 和 `worker` 两种，不能自定义类型，也不能再派子代理。
- 子代理的四个文件不在主区打开，只在父会话里显示它的工具行。
- 没有右侧检视面板，文件页就是主区里的四个标签。

## 已知问题

下面这些是读代码时发现、还没修的问题，按影响排序。

- **`write_file` 会跟随符号链接写出工作区。** 沙箱只对父目录取真实路径；目标文件若已经是指向工作区外的符号链接，内容先写到链接指向的位置，之后的复核发现越界才报错，那时文件已经改了。
- **永不执行的名单只认根目录和磁盘工具。** `dangerous.ts` 认得出递归删除整个盘或根目录的各种写法，但认不出用变量拼出来的路径，比如 `rm -rf "$DIR/"`；删用户目录、系统目录（`rm -rf ~`、`Remove-Item -Recurse C:\Windows`）也不在名单里。这些只按写操作要确认，点过「允许这一轮」就会执行。
- **`str_replace` 的单次替换会解释 `$` 模式。** 它用的是 `String.replace`，`new_string` 里的 `$&`、`` $` ``、`$'`、`$$` 会被替换成别的内容；`replace_all` 那条路径没有这个问题。
- **重启后，被 deferred 子代理领取的任务会卡在 `in_progress`。** 子代理只活在进程内存里。父会话可以用 `owner` 等于那个子代理的 id，替它完成任务。
- **一个任务文件损坏，整张清单都改不了。** 领取、完成在内的所有修改操作都会失败。
- **子代理调用 `subagent` 或 `ask_user` 时，整个子代理失败。** 宿主对这两个名字直接抛错，子代理循环没有接住。
- **shell 输出的几处细节。** 输出超过 `maxToolOutputChars` 时进程被结束，结果按成功返回。代码注释写明这是有意的，但只有标准输出时连截断标记都没有，模型可能以为命令已经跑完。另外，输出按数据块分别解码，中文等多字节字符可能在块边界乱码；超时或取消时，已经拿到的输出被丢掉。
- **拿不到部分 token 用量。** 请求不带 `stream_options.include_usage`，OpenAI 官方接口在流式下就不返回用量；子代理的用量完全不记录。
- **`read_skill` 的工具说明和技能使用规则相互矛盾。** 前者说结果里带技能目录，「方便按绝对路径运行脚本」；后者要求不要用 shell 读技能目录或跑脚本，改用 `run_skill_script`。
- **`web_search` 只适配 DeepSeek。** `searchBaseUrl` 存在于工具上下文里，但没有接进配置。
- **配置文件的可靠性。** 写入不是原子操作；解析失败时静默退回默认值和空密钥。
- **没有单实例锁。** 开两个实例会同时写同一份配置和同一个 `.agent/`。
- **界面。** 解释栏里的链接点不开。「重新问」会覆盖当前草稿，并带上草稿里的图片。续跑期间暂存的消息不附 `/技能名` 的正文。
- **`/mnt/x/…` 路径转换不看平台。** `openTargetNormalize.ts` 在 Linux 上也会把它改写成 `X:\…`。
- **`scripts/test-markdown.mjs` 跑不起来。** `ui.ts` 在模块顶层创建 `ResizeObserver`，还给 `document`、`window` 挂监听，纯 Node 里没有这些对象，一导入就报错。这个脚本没有接进 npm 脚本，所以一直没人发现。
