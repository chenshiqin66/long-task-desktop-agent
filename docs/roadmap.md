# 路线图与已知问题

这一页写四件事：不同会话怎么同时执行、刻意还没做的事、已经按代码改过的行为，以及还没修完的问题。前两节是设计取舍，第三节是改过之后的现状，第四节是还欠着的部分。

## 不同会话同时执行

5 是同时处于执行中的 runtime 个数，不是把主区切成 5 块。主区仍然只有一页。

`AgentRuntime` 仍然只服务一轮，没有改成内部多轮。同时执行靠外面的 `SessionRuntimePool`，键是规范化后的「工作区路径 + `sessionId`」。路径里的斜杠和大小写先折成同一种写法，避免 `C:\work` 和 `C:/work` 各占一个名额。

- 一条会话正在跑时再向它发送，仍是 `busy`；续跑留在这个对象里面。另一条会话另建一个对象，各自一份权限门和提问门，答复仍靠 `request_id` 配对。
- 正在执行的对象最多 5 个。第 6 次发送得到 `已有 5 个会话在执行`。第 6 次收件箱唤醒不报错，回执留在队列里，等名额空出来再打开那条会话时再试。
- 父轮次结束、并且没有后台子代理时，丢掉这个对象；下次发送按当时的配置新建。正在跑的那条，以及还有后台子代理的那条，继续用开始时的配置。后台子代理还在时，侧栏的圈继续转，名额和转圈一致。这一轮本身已经结束，输入框可以再发，停止按钮也不会去取消已经在后台的子代理。
- 切换或增加工作区不再拆掉别的会话还在跑的对象。删掉会话会取消这一轮并停掉它的后台子代理。重新加载页面会取消当时所有正在执行的对象，不再留一个还在跑、却没人能回答的 runtime。
- 每个对象只监视自己那条会话，避免一条跑完把续跑切到另一条上。

界面：

- 输入框只看当前这一条。没在跑就能发送；正在跑则按钮是「停止」，只取消这一条。别的会话在跑时，这里照常打字。
- 流式文字、工具条和权限条写进该会话自己的对话节点；切走后节点留着，后台继续往里面写。
- 侧栏里每个还占着名额的会话各自转圈，包括父轮次已经结束、后台子代理还在跑的那一条。某条停在权限确认或「等你回答」、而你正看着别处时，那一项换成不转动的等待标记，任务栏图标也会闪。

这一版不隔离的部分：同一工作区的两条会话各写各的 `.agent/sessions/<id>/`，对话不会串。`output_dir` 仍是模型在每次 `worker` 调用里填的相对目录，不是按会话分配的文件夹；这一版也不做跨会话互斥，两条会话写到同一路径时，后写的盖过先写的。读文件、改文件和跑命令同样作用在同一个项目目录上。解释侧栏仍是同一时刻只跑一个。不预先拉起空进程。同一个用户数据目录里再启动一次会退出，并把已有窗口带到前面。应用重启后，磁盘上的会话还在，正在跑的那一轮已经断了。

## 刻意还没做的

- 主会话不能写记忆。过时的条目由你改，或由你下一句说的话让后台改。
- 指令文件只有用户级和项目级两份 `AGENTS.md`。没有组织级，没有只在本机生效的私人文件，不展开 `@path`，不读父目录和子目录，也没有按路径生效的规则。
- 记忆不做向量检索，不每轮另调模型来挑选，也不自动整理。
- 子代理不读写记忆，解释侧栏不用记忆和指令文件。
- 记忆不跨机器同步，也不在团队里共享。
- 没有会话内的工作笔记。长任务里被整段丢掉的旧工具往返另作一个模块。
- 重新打开会话时不重画「已记住」那一行。
- 子代理只有 `explore` 和 `worker` 两种，不能自定义类型，也不能再派子代理。
- 子代理的四个文件不在主区打开，只在父会话里显示它的工具行。
- 没有右侧检视面板，文件页就是主区里的四个标签。
- 生视频和生音这一版还不能生成。选中这类模型后，只提示改选生文或生图，不会发出请求。

## 已经按代码改过的

这些原先记在下面的欠账里。没改完的部分仍留在下一节。

- **只开一个窗口。** 同一个用户数据目录里再启动一次，新进程退出，并把已经开着的窗口带到前面。
- **`write_file` 不跟随已有的符号链接。** 目标已经是符号链接时，写入前拒绝。硬链接仍会写到另一份。
- **递归删除家目录和系统目录直接拒绝。** 整盘、根目录、用户主目录，以及 `C:\Windows`、`C:\Users`、`C:\Program Files`、`C:\Program Files (x86)`、`/etc`、`/usr`，点过允许也不执行。单独一个变量再只加 `/` 或 `/*` 同样拒绝。还认不出的写法见下一节。
- **重启打断的 deferred 子代理会放开任务。** 下次打开会话或再发送时，进程编号对不上、仍标着在跑的记录把领取的任务放回待办，并记成中断。父会话仍没有那次回执。
- **一个读不出来的任务文件不再挡住整张清单。** 别的任务可以新建、领取和完成。这个文件留在原地，依赖它的任务仍算被挡住。
- **子代理不能提问，也不能再派子代理。** 它若调用这两个，得到的是一条错误结果，这一轮继续。父会话里这两个名字仍由 runtime 接住，不会变成一条普通结果。
- **超时或取消留下已经拿到的输出。** shell 和技能脚本都如此，这一次仍算失败。输出按 UTF-8 解码。命令输出顶到上限时仍算成功，并在末尾标出被截断。技能脚本顶到上限时还没有这句标记。
- **流里有用量才记。** 请求带上用量字段。网关因此返回 400，且正文提到这个字段时，去掉它再试一次。流里没有数字就不记，也不估算。父会话、子代理和解释都按这一条。
- **搜索有自己的模型类型。** 在模型页添加类型为「网搜」的模型，`web_search` 就指向它，和对话模型各有一个「当前」，同时生效，不跟随对话模型。返回体仍只认 DeepSeek 的 JSON。
- **配置先写到临时文件再换上。** 坏的 `config.json` 会改名备份，启动时说明备份路径。应用仍以空密钥启动。改名失败时原文件还在，之后的保存可能盖掉它。
- **解释栏里的链接和主对话一样可以打开。**
- **「重新问」再发原来的文字和原来的图片、视频。** 输入框里正在写的字和已经选上的附件留在原地。两条消息用会话里的同一个图片或视频文件。只有图片或视频、没有文字的问题也有这个按钮。
- **续跑期间暂存的那句话会附上技能正文。** 找不到或已停用就跳过，这一轮不因此失败。完成通知本身不附正文。
- **`scripts/test-markdown.mjs` 可以在普通 Node 里跑。** 它仍没有接进 `npm test`。

## 已知问题

下面这些是读代码时发现、还没修完的问题，按影响排序。

- **`write_file` 不拒绝硬链接。** 目标若已经是指向工作区外的硬链接，写入会改到那一份。符号链接在写入前拒绝。
- **一部分删除仍然认不出。** `"$DIR/build"`、先 `cd` 再 `rm -rf *`、写在脚本里的删除，以及 `~/code`、`C:\Users\某个账户` 这种再往下的目录，都不在永不执行的名单里。点过「允许这一轮」就会执行。
- **重启打断的 deferred 子代理没有回执。** 打开会话或再发送时，进程编号对不上、仍标着 `running` 的子代理会把领取的任务放回 `pending`，meta 记成中断。父会话不会收到那次未完成的回执。
- **一个读不出来的任务文件留在原地。** 别的任务可以新建、领取和完成，新编号会跳过这个文件占着的号。领取、完成、修改、删除这个坏编号都会被拒绝，文件不会被修好或删掉。依赖它的任务一直算被挡住，因为没法知道它有没有完成。
- **流里没有用量就不记。** 请求带 `stream_options.include_usage`。网关若因为这个字段返回 400，且正文提到它，会去掉该字段再试一次。流里没有 `usage` 时，父会话、子代理和解释都不写 token 数，也不补一个估算值。
- **`web_search` 只认 DeepSeek 的返回格式。** 网搜模型的 Base URL 和 API Key 决定请求发往哪里，不回退到对话模型的密钥。别家的 JSON 对不上，结果仍然是一次失败。
- **配置文件的可靠性。** 坏的 `config.json` 会改名为 `config.json.broken-<时间>`，启动时说明备份路径。应用仍以空密钥启动，要自己把备份改回去。改名失败时文件留在原地，之后的保存会盖掉它。
