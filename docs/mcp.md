# MCP

MCP server 是一份会动的工具表。它跟技能不是一回事：技能是 `SKILL.md` 和脚本，MCP server 是一个子进程或一个远程端点，握手之后把工具交给模型。配置在用户目录，所有工作区共用。子代理和解释侧栏不带这些工具。

## 配置文件

```text
~/.long-task-agent/mcp-servers.json
```

和 `config.json` 分开。写入先落到临时文件再改名。文件不是合法 JSON，或者某几条读不出来时，应用不去改它，连接页顶上说明原因，已经能读出来的条目照常连接。这时不能再添加或修改，先把文件改好再重启。

密钥留在这个文件里：stdio 的环境变量，或 URL 的查询参数。连接页、报错和交还给模型的工具结果会把 `key`、`token`、`secret` 这类参数打码，也会把配置里长度不少于 6 的环境变量值打成 `***`。模型看不到地址本身。

## 两种传输

**本机命令。** `command`、参数列表、环境变量、可选工作目录。进程由 SDK 以 `shell: false` 拉起，环境只带一份安全的父进程变量（`PATH` 等），再叠上你填的变量，不会把父进程里的其他密钥带进去。Windows 上命令名是 `npx`、`npm`、`pnpm`、`yarn` 时，实际启动的是对应的 `.cmd`。高德的本机接法是：

```text
命令  npx
参数  -y
      @amap/amap-maps-mcp-server
环境  AMAP_MAPS_API_KEY=你的 Web 服务 Key
```

官方要求本机 Node 22.14 或更高，npm 源用官方源。这套包没有专属地图、导航和打车。

**远程地址。** Streamable HTTP，一个 `http` 或 `https` URL。高德现在推荐的是这一条，专属地图、导航和打车只在这里：

```text
https://mcp.amap.com/mcp?key=你的Key
```

Key 的服务平台要选「Web 服务」。重定向只跟随同一来源，避免密钥被带到别的主机。不做 OAuth，不做资源和提示词，这个应用自己也不对外当 MCP server。

## 连接页

侧栏「连接」在主区打开一页。空的时候说明两种填法。添加时填名称、传输和对应字段。名称是 1 到 32 位小写字母、数字和单个连字符，保存后不能改名。

每张卡片有状态（已停用、连接中、已连接、失败）、打码后的命令或地址、工具名、开关、自动放行、重新连接、修改、移除。改传输、命令、地址或环境变量会重新握手。只改自动放行不重连。

自动放行只作用于这个 server 已连上的工具。写文件、命令和其他 server 仍要确认。高德这种查询适合打开，否则规划一次行程要逐条点允许。

## 模型看到的工具

名字是 `mcp__<server>__<tool>`。远程名字里不能用在函数名里的字符会换成下划线；拼出来超过 64 个字符时，尾部收成哈希。一个 server 最多注册 64 个工具。

每一轮开始时把当时已连接的工具拍进这次循环。添加、断开和失败从下一轮才改变模型看见的表。调用本身走当前连接：这一轮中途重连成功，后面的调用用新进程。

这些工具不进入子代理的工具子集，解释侧栏仍然只有 `web_search`。

## 确认

没开自动放行时，每次调用都要确认。卡片标题是「需要确认这次 MCP 调用」，按钮是「允许这一次」。这次允许不带上本轮剩下的写操作和命令，后面的 MCP 调用也会再问。点过内置工具的「允许这一轮」之后，MCP 调用仍会再问。

工具结果按 `maxToolOutputChars` 截断。服务器报错变成 `is_error` 的工具结果，这一轮继续。
