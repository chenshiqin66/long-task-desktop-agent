# 模型类型、生图与媒体

日期：2026-11-18

> **状态：部分过时。** 生文、生图与上传媒体仍按本文；**生视频已落地**（派欧云 MiniMax H3 异步协议、四型号参数、结果写入 `videos/`）。参考素材模式与对话内覆盖尚未接通。生音仍未接入。当前行为以仓库代码、[README](../../../README.md) 和 [架构](../../architecture.md) 为准，不要仅按本文实现生视频。

对话要能按当前选中的模型走不同调用路径：生文继续走带工具的对话接口，生图走图片生成接口并把图展示在对话里。用户还可以在输入框旁上传图片和视频，给多模态生文模型看。不另做意图识别器。第一版在本地 `main` 上开发。

## 已定行为

### 模型类型

每条模型记录增加一个类型，界面文案和存储值如下：

| 界面 | 存储值 |
| --- | --- |
| 生文 | `text` |
| 生图 | `image` |
| 生视频 | `video` |
| 生音 | `audio` |

已有记录没有这个字段时，一律视为生文。模型页的表单里用下拉框选择类型；列表和输入框旁的模型选择器都要能看出当前类型。

类型由用户指定，不按 Base URL 或模型名猜测。

### 按当前模型分流

发送时看当前选中模型的类型，这一轮只走一条路径：

- 生文：仍请求 `${baseUrl}/chat/completions`，带工具列表，行为与现在的对话循环相同。用户本轮附带的图片和视频作为多模态内容一并发送。
- 生图：请求 `${baseUrl}/images/generations`，不带工具，不进入对话循环。用本轮提示词生成图片，存进当前会话并展示在助手气泡里。
- 生视频、生音：第一版不调用任何模型接口。对话里提示「这个类型第一版还不能用，请改选生文或生图」，本轮结束。

不在发送前加意图识别，也不因为用户说了「画一张图」就改走生图。选错模型导致的失败，把服务返回的错误展示出来。

应用仍然把用户填写的 Base URL 当作前缀，不自动改写。生文拼 `/chat/completions`，生图拼 `/images/generations`。某条模型调用失败时，先检查这条的 Base URL 是否就是该接口的前缀。

### 生图请求

第一版请求体只发：

- `model`：该条记录里的模型名
- `prompt`：用户这一轮输入的文本
- 若本轮用户附带了图片，按该接口常见的参考图字段一并送出（例如 `image`，值为 data URL 或数组）

不发尺寸、格式等可选项，沿用接口默认值。本轮若附带了视频，不发给生图接口，并提示用户先去掉视频，或改用生文模型。

生图不是流式接口。发出后，对话里先出现一条助手占位，例如「正在生成图片」。成功后把返回的图保存下来，占位换成带图的助手消息；失败则去掉占位，展示错误，不留下空气泡。用户点停止时，中止这次请求。

返回值同时兼容 base64 和图片 URL：是 URL 时由应用下载再保存。保存规则与现有用户上传图片相同：字节写在会话目录的 `images/` 下，消息里只存引用（`id`、`mime`、相对路径）。路径仍符合现有校验，例如 `images/img_<hex>.png`。

助手消息也可以带 `images`。气泡在只有图、没有文字时也要显示。对话记录重新打开后，已生成的图仍能看见。

后续轮次里，更早消息上的媒体按现有图片规则处理：只把最新一条用户消息里的媒体以字节发出，更早的改成一行说明，不改磁盘文件。

### 上传视频

输入框旁已有「添加图片」，再并排增加「添加视频」。解释面板如果已有添加图片，同样加上添加视频。

第一版约定：

- 容器：`video/mp4`、`video/webm`、`video/quicktime`
- 一条用户消息最多 1 个视频，图片仍最多 4 张，可以同时存在
- 单个视频不超过 20 MiB；空文件或超限时提示，不发送
- 字节写在会话目录的 `videos/` 下，消息里只存引用。相对路径形如 `videos/vid_<hex>.mp4`

最新一条用户消息里的视频，在生文请求里做成内容块发出，形状与现有图片块并列：

```text
{ "type": "video_url", "video_url": { "url": "<data URL>" } }
```

更早轮次的视频不重复发字节，只留一行说明，例如「此轮附有 1 个视频，未再次发送。」

对话气泡里，用户上传的视频要能播放。重新打开会话后仍能播放。

### 模型页按钮

每条模型记录增加「复制」。点击后立刻新建一条记录：字段与原来相同，换新的 id，名称在原名称后加「（副本）」，类型一并复制。不会改成当前模型。新建后打开这条的编辑表单，方便用户改名称或模型名。

按钮布局和显隐：

- 「使用」始终在该行最右侧，一直可见。当前正在使用的那一条不显示「使用」，仍显示「当前」标记。
- 「复制」「修改」「移除」默认隐藏，鼠标移到该条记录上，或键盘焦点落在该条里时才显示。

### 其他现有行为

解释面板只用于生文。当前模型是生图、生视频或生音时，解释入口不可用，并说明要改选生文模型。

记忆提取、会话停止、密钥不写进日志，这些保持现有规则。生图成功后的助手消息和用户提示词，仍按现有规则参与记忆提取。

## 错误处理

- 生图或生文请求失败：用现有对话错误展示方式显示状态码和接口返回的说明，不重试成另一种类型。
- 下载生图 URL 失败：视为生图失败。
- 上传类型或大小不符：在发送前用现有状态栏提示，不发出请求。
- 没有提示词、也没有可发送的媒体：生文与现在一样；生图必须有非空提示词，否则提示用户输入后再发送。

## 测试

先写测试再改实现，覆盖至少：

- 缺省类型视为生文；四种类型读写后保持原值
- 按类型分流：生文走 `chat/completions` 且可带图和视频；生图走 `images/generations` 且不带工具；生视频、生音不发请求
- 生图成功后，助手消息带有保存后的图片引用；失败不写空气泡
- 历史媒体只在最新用户消息里以字节发出，更早的变成说明
- 视频大小、数量、类型校验
- 复制产生新 id、名称带「（副本）」、字段与类型与原来一致，且不切换当前模型

- 不实现生视频、生音的生成接口

- 第一版不在模型页或输入框提供尺寸、比例、格式等生成参数
- 不自动改写用户填写的 Base URL 或模型名
