# 生视频：型号 × 素材模式用法要点

日期：2026-11-23

> 面向产品 / UI：说明「每个型号能出什么」「每种素材模式要什么附件与参数」，方便设计模型页与对话侧控件。  
> 实现以仓库代码为准（`packages/core/src/config/videoOptions.ts`、`provider/videoGeneration.ts`、`runtime/agentRuntime.ts`）。上游协议为派欧云转发的 MiniMax H3（`https://api.ppio.com`，路径 `/v3/minimax/v2/...`）。  
> 价格文案来自型号 blurbs，**以派欧云账单为准**。官方输入规格另见 [MiniMax 视频生成指南](https://platform.minimax.cn/docs/guides/video-generation)。

相关文档：[界面行为](ui-behavior.md)（模型页与气泡）、[架构](architecture.md)（runtime 分流）、[数据模型](data-model.md)（落盘与 context 行）、[路线图](roadmap.md)（对话内本轮覆盖尚未做）。

## 1. 先分清两层

| 层 | 职责 | 今日 UI |
| --- | --- | --- |
| **型号（model id）** | 决定分辨率档、时长上下限、部分画幅规则、计价 | 模型页四个 Tab：Lite / Highspeed / Max / H3 |
| **素材模式（mode）** | 决定本轮附件形态与请求体里的 `role` | 模型页「素材模式」方框启用 + 圆点默认；对话只用默认，**尚无本轮覆盖** |

四档型号都支持全部五种素材模式；差别主要在分辨率、时长下限、参考模式下 Lite 的画幅限制，以及定价/免费图张数（营销信息，非协议字段）。

**对话侧当前行为：** 提示词必填；附件按**当前默认模式**校验；选中生视频时 composer 附件上限放宽到参考素材上限（图 9 / 视 3 / 音 3），但若默认模式仍是首帧等，张数不对会报错。

## 2. 型号一览（输出规格）

| 型号 `model` | 定位（产品文案） | 分辨率 | 时长（整秒） | 参考模式 `adaptive` | 输入图免费张数（文案） |
| --- | --- | --- | --- | --- | --- |
| `MiniMax-H3-Lite` | 轻量试错 / 批量 | 480P、768P | 4–15 | **禁止**（须固定比例） | 前 5 张 |
| `MiniMax-H3-Highspeed` | 日常高频 | 480P、768P | 4–15 | 允许 | 前 5 张 |
| `MiniMax-H3-Max` | 多素材扩展档 | 480P、768P | **5**–15 | 允许 | 前 2 张 |
| `MiniMax-H3` | 旗舰成片 | **768P、2K** | 4–15 | 允许 | 前 5 张 |

共用画幅枚举（设置页可勾选启用集）：`16:9`、`9:16`、`1:1`、`4:3`、`3:4`、`21:9`、`adaptive`。

默认（未改设置时）：模式 `文生`、画幅 `16:9`、分辨率取该型号首选（H3→768P，其余→480P）、时长取该型号下限。

**UI 含义：**

- 型号 Tab 切换时：分辨率列表、时长轴可用区间、`adaptive` 是否可选，都要跟着变（Lite + 启用了参考模式时，启用集里必须至少有一个非 `adaptive` 画幅）。
- Max 的时长轴不要画出 4 秒可选段。
- H3 Tab 不要出现 480P。

## 3. 五种素材模式（跨型号相同）

存储值见 `VIDEO_GEN_MODES`。图生与参考**互斥**：同一请求不能混用 `first_frame`/`last_frame` 与 `reference_*`。

### 3.1 文生视频 · `text`

| 项 | 要点 |
| --- | --- |
| 用途 | 纯文字出片；可附 **0～1** 张图（兼容：一张时按首帧发出） |
| 必填 | 提示词（1–7000 字） |
| 附件 | 0 图；或 1 图（将当作首帧，见下） |
| 禁止 | ≥2 张图（应改「首尾帧」）；参考视频 / 参考音频 |
| 画幅 | **必须固定比例**，不能 `adaptive`。有那 1 张兼容图时，实现上会改走首帧路径并强制 `adaptive` |
| 请求体 | 仅 `text`；或 `text` + 一张 `role=first_frame` |

**UI：** 文生是默认「最少控件」路径：提示词 + 可选 1 张参考图。摘要不必强调「首帧」 unless 用户已附图。若用户塞了第二张图，应提示改模式，而不是静默丢掉。

### 3.2 图生 · 首帧 · `first_frame`

| 项 | 要点 |
| --- | --- |
| 用途 | 指定**起始画面**，文字描述运动与镜头 |
| 附件 | **恰好 1 张**图片 |
| 画幅 | 实现强制 `adaptive`（跟图走）；设置页画幅圆点对本轮无实质影响 |
| 请求体 | `text` + `image_url` `role=first_frame` |

**UI：** 附件区应突出「首帧」槽位（单图、可预览、可替换）。分辨率 / 时长仍可选；画幅控件可灰显并注明「由图决定」。

### 3.3 图生 · 尾帧 · `last_frame`

| 项 | 要点 |
| --- | --- |
| 用途 | 指定**结束画面** |
| 附件 | **恰好 1 张**图片 |
| 画幅 | 同首帧，强制 `adaptive` |
| 请求体 | `text` + `role=last_frame` |

**UI：** 与首帧对称，标签改为「尾帧」。不要和首帧做成两个可同时填的槽，除非模式切到「首尾帧」。

### 3.4 图生 · 首尾帧 · `first_last`

| 项 | 要点 |
| --- | --- |
| 用途 | 从画面 A 过渡到画面 B |
| 附件 | **恰好 2 张**，顺序：`[0]=首帧`，`[1]=尾帧` |
| 画幅 | 强制 `adaptive` |
| 请求体 | `text` + `first_frame` + `last_frame` |

**UI：** 两个有序槽（左首 / 右尾，或上首 / 下尾），支持拖拽换序。校验文案要写清顺序，避免「两张图」含糊提示。

### 3.5 参考素材 · `reference`（r2va）

| 项 | 要点 |
| --- | --- |
| 用途 | 锁角色 / 动作 / 镜头 / 风格 / 声音等；多模态组合 |
| 附件下限 | 至少 **1 张图或 1 段视频** |
| 附件上限 | 图 ≤ **9**；视频 ≤ **3**；音频 ≤ **3**；三者合计 ≤ **12** |
| 禁止 | **仅音频**（必须再配图或视频） |
| 画幅 | **不**强制 `adaptive`；可用设置值。**Lite** 若选了 `adaptive`，运行时落到固定比例（默认 `16:9`） |
| 提示词 | 可按出现顺序用 `<Picture 1>`、`<Video 1>`、`<Audio 1>` 引用（上游惯例；本应用不强制改写提示词） |
| 请求体 | `text` + 若干 `reference_image` / `reference_video` / `reference_audio` |

**官方素材规格（设计校验 / 文案时可引用；应用本地上传上限可能更严，见 §5）：**

| 类型 | 格式（官方） | 单文件 | 其它 |
| --- | --- | --- | --- |
| 图 | JPG/JPEG/PNG/WEBP/HEIC/HEIF | ≤30 MB | 边长 [256, 5760]；宽高比约 0.4–2.5 |
| 视频 | H.264/H.265；内嵌音 AAC/MP3 | ≤50 MB | 单段时长 2–15 s；总时长 ≤15 s；≤3 段 |
| 音频 | WAV、MP3 | ≤15 MB | 单段 2–15 s；总时长 ≤15 s；≤3 段 |
| 请求体 | — | 合计 ≤64 MB | 大文件宜 URL，勿堆 Base64 |

**UI：**

- 需要**三类附件入口**（图 / 视 / 音），并显示剩余配额（如「图 2/9」）。
- 仅音频时发送按钮旁即时应拦截，不要等服务端。
- 摘要芯片示例：`参考素材 · 768P · 5s · 16:9 · 图2 视1`。
- Lite 下画幅选择器隐藏或禁用 `adaptive`。

## 4. 模式 × 附件：设计速查

| 默认模式 | 图 | 视 | 音 | 画幅实际发出 | Composer 应强调的控件 |
| --- | --- | --- | --- | --- | --- |
| `text` | 0–1 | 0 | 0 | 固定比例（0 图）；1 图时变 `adaptive` | 提示词；可选单图 |
| `first_frame` | 1 | 0 | 0 | `adaptive` | 单槽「首帧」 |
| `last_frame` | 1 | 0 | 0 | `adaptive` | 单槽「尾帧」 |
| `first_last` | 2（有序） | 0 | 0 | `adaptive` | 双槽有序 |
| `reference` | 0–9 | 0–3 | 0–3 | 设置值（Lite≠adaptive） | 三类配额 + 提示词引用说明 |

所有模式：**提示词必填**；异步创建 → 轮询 → 下载，结果进会话 `videos/`。

## 5. 本应用与上游的差异（设计时别混）

| 项 | 本应用现状 | 上游 / 备注 |
| --- | --- | --- |
| 上传视频体积 | 用户上传约 **20 MiB** | 官方参考视频可至 50 MB |
| 上传音频体积 | 会话约 **25 MiB** | 官方参考音频 ≤15 MB（超限可能任务失败） |
| 图片 | 渲染进程会压缩再上传 | 官方单图 ≤30 MB |
| 生文消息视频数 | 生文等多模态仍偏「每条 1 视频」语义 | 参考模式在**生视频 kind**下可到 3 |
| `generate_audio` | **未接** UI / 请求字段 | 官方可控制成片是否有声，默认有声 |
| 本轮覆盖模式/分辨率/时长 | **未做**（只用模型页默认） | 产品缺口见路线图 |
| 素材公网 URL | 目前 data URL / Base64 | 大素材推荐 URL，避免 64 MB 体 |

## 6. 建议的 UI 元素映射（不含实现承诺）

### 6.1 模型页（已有骨架）

按**型号 Tab** 各存一份 `videoByModel[id]`：

- 启用集：模式 / 分辨率 / 时长上限轴 / 画幅（方框）
- 默认：模式 / 分辨率 / 时长 / 画幅（圆点）
- Lite：启用「参考素材」时，校验「至少一种非 adaptive 画幅」

### 6.2 对话 composer（生视频 kind 时）

保持「提示词 + 附件」为主，**不要**把模型页整表塞进输入框。推荐：

1. **一行摘要芯片**（模式 · 分辨率 · 时长 · 画幅 · 附件计数）  
2. 点击打开 **popover**：仅本轮覆盖（仍受启用集约束）+「恢复默认」  
3. **按模式切换附件槽布局**（上表「Composer 应强调的控件」）  
4. 可选：按附件数量**建议切换模式**（0 图→文生，1 图→首帧，2 图→首尾帧，有视频/多图→参考），用户可撤销  

生图 kind 用另一套更短的参数 popover，勿与生视频共用同一表单。

### 6.3 错误与空态文案应对准模式

| 情况 | 文案方向 |
| --- | --- |
| 空提示词 | 生视频请先输入提示词 |
| 首帧/尾帧张数不对 | 恰好一张；指明首或尾 |
| 首尾帧不是两张 | 按顺序两张：第一张首帧，第二张尾帧 |
| 文生 ≥2 图 | 改用首尾帧 |
| 非参考却带了视频/音频 | 改用参考素材，或去掉该附件 |
| 参考无图无视 | 至少附一张图片或一段视频 |
| 参考仅音频 | 参考音频需同时附图片或视频 |

## 7. 请求体角色速记（给联调 / 高级说明）

| mode | content 中的 media `role` |
| --- | --- |
| `text`（0 图） | （无） |
| `text`（1 图）/ `first_frame` | `first_frame` |
| `last_frame` | `last_frame` |
| `first_last` | `first_frame` + `last_frame` |
| `reference` | `reference_image` / `reference_video` / `reference_audio` |

创建：`POST {apiRoot}/v3/minimax/v2/video_generation`  
查询：`GET {apiRoot}/v3/minimax/v2/query/video_generation/{task_id}`  
`apiRoot` = Base URL 去尾斜杠后再去掉可选的 `/v1`。
