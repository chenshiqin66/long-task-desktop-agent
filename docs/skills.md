# 技能

技能是一个带 `SKILL.md` 的文件夹：一段说明，可选的参考资料和脚本。它装在用户目录，所有工作区共用。

设计上分三层，按需展开：每次请求都带上已装技能的名字和一句话描述；正文只在用户写了 `/技能名`、或模型调用 `read_skill` 时才进上下文；脚本经 `run_skill_script` 执行，要确认。这样装十个技能也不会撑爆上下文，模型又知道有哪些可用。

## 文件格式

```text
~/.long-task-agent/skills/
  <name>/
    SKILL.md            必需
    ...                 参考资料、脚本，任意结构
  .skill-settings.json  停用名单：{"disabled": [...]}
```

`SKILL.md` 以 frontmatter 开头，`name` 和 `description` 必填，支持 `>`、`|` 多行写法：

```markdown
---
name: pdf-tools
description: 拆分、合并、提取 PDF 文本。
---

正文：什么时候用、怎么用、脚本在哪。
```

名字只能是小写字母、数字和单个连字符（`^[a-z0-9]+(?:-[a-z0-9]+)*$`），1 到 64 个字符。名字就是目录名，所以它必须是一段安全的路径。

## 安装与管理

在技能页点「+ 添加技能」，选一个含 `SKILL.md` 的文件夹。安装时先解析 frontmatter，再把文件夹复制到 `skills/<name>/`，跳过 `.git`、`node_modules`、`__pycache__`。复制先进临时目录，完成后整体改名就位，中途失败不会留下半个技能。同名技能已经装过时直接拒绝：要更新，就直接改技能目录，或者先卸载再添加。

复制时会解析符号链接：指向源文件夹之外、或者成环，整次安装失败；指向源文件夹之内，按内容复制，副本里不留符号链接。安装是一份快照，之后再改原来的文件夹，副本不变。

把符合格式的文件夹直接拷进 `skills/<name>/` 也算安装，因为列表每次都重新扫这个目录。目录名必须等于 frontmatter 里的 `name`，`SKILL.md` 也要能解析，否则这个技能不出现，也不报错。

技能页从左下角的「技能」按钮进入，可以停用、启用、卸载技能，点卡片打开技能目录。卸载会删掉整个技能目录，包括你在里面直接改过的内容，而且不需要确认。主进程递归监视技能根目录，400 毫秒防抖后通知界面刷新，所以直接在文件管理器里改技能也会被看到。

## 模型怎么用技能

**目录。** 每次请求的 system 里都有 `# Installed skills`，列出已启用技能的名字和描述，后面跟一段使用规则。没装技能时，这一段不出现。

**正文。** 用户消息里写 `/pdf-tools`，这个技能的正文和目录路径就附进这一轮的 system，只对这一次发送有效。输入框里打 `/` 会弹出补全。

识别规则是：消息开头或空白之后的 `/`，紧跟一个合法的技能名，名字后面不能接着 `/`、`\` 或「`.` 加字母数字」，那是路径还没写完。反引号里的代码和代码块不算。所以「看看 /etc/hosts」「/api/v1/users 返回 500」「读一下 /notes.md」都不会被当成技能，「用 /demo，做个幻灯片」「use /demo.」会。规则只有一份，在 `packages/core/src/skills/tokens.ts`；界面发送前经 IPC 调用同一个函数检查草稿。

名字不存在或已停用时，界面显示「未知技能 /名字。如果这是路径，放进反引号里：`/名字`」或「技能 /名字 已停用」，消息不发送，草稿保留。只有一段的路径，比如「cd /tmp 看看」，和技能名长得一样，会被当成技能 `tmp` 拦下来，这时按提示放进反引号。这是有意的取舍：把认不出的名字当文字直接发出去，`/pdf-tool` 这种少打一个字母的笔误就会悄悄发出去，模型拿不到技能正文，用户也不知道。

完成通知开出续跑轮时暂存的那条消息也不附正文，里面的 `/技能名` 只作为文字进入对话。

模型也可以自己调用 `read_skill` 读正文或技能目录里的文件，按 `maxReadChars` 截断；正文已经附在上下文里时，它直接说明已附上。已停用的技能，`read_skill` 和 `run_skill_script` 都会拒绝。之前用户轮次里 `read_skill` 的结果，在之后的请求里会换成一句「此前读过技能 X 的正文。需要时再调用 read_skill。」，不重复占预算。

**脚本。** `run_skill_script` 按扩展名选解释器：`.py` 用 `python`，`.js`、`.mjs`、`.cjs` 用 `node`。

- 参数是数组，最多 32 个，每个最长 2000 字，不能含 NUL。不经 shell，所以参数不会被 shell 再解释一遍。
- 工作目录是当前工作区，超时用 `bashTimeoutMs`，输出受 `maxToolOutputChars` 限制。
- 脚本的真实路径必须在该技能目录内；已停用的技能不能运行。
- 分级是 `write`，要确认。脚本以你的用户权限运行，不受路径沙箱限制。

使用规则还要求模型不要用 shell 读技能目录或跑脚本，也不要修改技能目录。这是提示词约束，不是强制，见 [安全模型与已知边界](tools-and-permissions.md#安全模型与已知边界)。

## 子代理里的技能

子代理可以 `read_skill`，不能 `run_skill_script`。子代理任务正文里的 `/技能名` 同样会附上正文；找不到或已停用时静默跳过，不让整个委派失败。
